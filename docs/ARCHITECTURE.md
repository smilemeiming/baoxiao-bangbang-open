# 架构与边界

本文主要描述微信小程序。Windows 应用使用独立的本地存储和离线 OCR，复用分类、字段归一化及 Excel 模块；桌面文件关系见 [逐文件说明](FILE_GUIDE.md)，操作和数据保存见 [使用手册](USER_GUIDE.md)。

`app.js` 读取初始化生成的 `config.local.js`。只有 `cloudEnvId` 非空且支持 `wx.cloud` 时才启用云服务。

首页和总览共用 `utils/invoice-import.js`：识别 → 辅助单据过滤 → 原件归档 → 历史配对 → 本地保存。详情页保存人工修正，报表使用最终存储数据。

云函数通过 `paddleocr-client.js` 调用远程 OCR，`normalizer.js` 将文本和表格归一化，也支持腾讯云 OCR。前端本地识别函数解析文件名用于规则和回归测试，不等价于图片内容 OCR。

记录使用 `invoice_reimbursement_items_v1` 本地存储键，原件位于用户目录 `invoice-archive`。`report.js` 直接构建包含 XML 的 ZIP 工作簿，不依赖额外表格库。

Excel 中的归档路径是设备本地路径；发送报表不会自动发送原件。登录、云同步、审批流、完整备份恢复和自动云文件清理尚未实现。

历史配对规则是同平台、日期差不超过一天、金额差不超过 5%。真实导入目前过滤非航空行程单；配对模块和示例保留作兼容与回归，不作为新增导入能力宣传。

部分分类规则分别在前端和云端维护。导入重试沿用重新导入流程，去重和原记录更新仍需改进。删除恢复是最近操作恢复，不是长期回收站。
